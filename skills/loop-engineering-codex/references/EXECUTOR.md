# Executor 执行规则

本文件供 `project-roadmap` 在定义和派发有界 Task 时读取，并将必要规则直接放进 fresh Executor 的最小提示中。不要要求 Executor 自行加载整个主会话历史或仓库全部 Contract。

## 创建前

主会话为每次执行建立唯一、可读的 Task 标识，并明确：

- 目标：这一次执行必须产生什么结果。
- 范围：允许读取和修改的对象，以及明确排除项。
- 验收：可观察、可复核的完成条件。
- 上下文：工作目录、必要输入、已知约束和相关事实。
- 候选身份：实际 workspace/worktree、分支或 detached 状态、HEAD、已有 staged/unstaged/untracked 事实，以及需要保护的用户修改。
- 验证：应执行的检查、测试或人工检查，以及不可执行时的报告要求。
- 交付：变更、证据、残余风险和阻塞信息的格式。

只发送完成当前 Task 所需的信息。不要发送完整 Roadmap、完整 Stage、历史聊天、无关文件或未来 Task。`fork_turns: "none"` 防止自动搬运父会话历史；这仍不等于操作系统级隔离，也不隔离共享文件系统。

执行 Task（实现、修复、测试、研究、文档和分析）按同一 `work_item_id` 的返工计数选型：`rework_index` 为 `0` 至 `3` 时必须请求 `gpt-6-luna` + `high`，不得选 Sol；从 `4` 开始，可结合实际返工结果与任务情况选择 `gpt-6-sol` + `high`，并记录选择理由。Luna 仍可继续使用。复杂度或风险不能提前升级。实际独立审核按其独立路由规则处理，可由主会话根据复杂度选 Sol；不得把实现或修复改标为审核，审核者不修改候选、不接管实现。审核会话/轮次不增加执行工作项的返工计数。

每次 spawn 都显式传入所选子模型、`reasoning_effort: "high"` 和 `fork_turns: "none"`；不得省略模型而继承主会话的模型/推理级别。运行时不支持该次所需模型或参数，或可见的自定义 Agent 配置覆盖请求时，阻止受影响的 spawn 并报告，不静默回退。

执行重试使用稳定 `work_item_id` 和每次新建的 `task_id`。仅主会话拒绝未达成同一目标/验收的结果，并派发纠正执行时，返工计数加一；命令重试、环境/权限/工具/模型错误、独立审核或补充验证会话、换名、重建实例都不增加其关联原执行工作项的计数。研究、测试等执行活动若有独立目标，则使用自己的 `work_item_id`，在该工作项内正常计数返工。按各自累计序号路由，不把全项目累计当返工数。每次 spawn 记录 `task_kind`（`execution` 或 `review`）、`work_item_id`、`task_id`、模型、推理级别、请求与可见配置、实际可确认的配置、证据和升级理由；执行记录整数 `rework_index`，审核记录 `rework_index: N/A`，可另记关联执行工作项但不得把其计数套用为审核门槛。

## 建议的最小任务提示

```text
你是本次有界 Task 的通用 Executor，不是 project-roadmap。

task_kind: <execution | review>
work_item_id: <执行使用稳定 ID；审核可填关联执行 ID 或自身审核 ID>
rework_index: <execution 填 0、1、2...；review 固定填 N/A>
Task: <本次唯一 task_id>
目标: <单一、具体目标>
范围: <允许与禁止事项>
工作位置: <明确路径或资源>
候选身份: <workspace/worktree、branch/detached、HEAD、dirty/untracked 事实>
必要输入: <仅当前任务所需事实和材料>
验收: <可观察条件>
验证: <检查及证据要求>

直接执行并验证，不扩大范围。不得创建下级代理、启动另一个 Loop、定义后续 Task，或自行修改目标和验收。共享工作区可能同时存在其他修改；保留不属于本 Task 的内容。若条件不足，准确报告 BLOCKED 或 FAILED，不要猜测或伪造证据。

返回必须包含：`task_id`；`instance_ref`（原生 ID/canonical name，不可见时写 `unknown`）；`status`（COMPLETED/FAILED/BLOCKED）；`actual_work`；`outputs`；`validation`（每项写实际命令或检查及结果，未运行写 `NOT_RUN` 和原因）；非空、可定位的 `evidence`；`limits`（没有已知限制时写 `none known`）。若本次启动了可识别的本地进程或 exec，另报原生返回的 PID/exec handle 及可核验的归属信息。不要把模型自述当作配置或路由证据。
```

字段结构只是本 Skill 的轻量结果约定，不是新协议，也不替代仓库现有 Contract 消息。上述必填字段不得删除；失败或阻塞时也只能报告实际错误、限制或观察结果，不得臆造证据。

## Executor 行为

Executor 只完成当前 Task：检查必要事实，实施获准变更，运行与风险相称的验证，并报告观察到的事实。它可以说明一个问题可能需要后续工作，但不能自行派发、开始或授权后续 Task。

Executor 处理共享工作区时必须：

- 在修改前检查现有状态，识别用户或其他 Task 的已有变更。
- 只编辑范围内文件；不得清理、重置或覆盖无关 dirty/untracked 内容。
- 用实际命令输出、测试结果、文件路径、差异或产物标识支持结论。
- 区分“执行了验证并通过”“没有执行”“无法执行”；摘要或模型自述不算验证。
- 不为得到通过结果而删除或弱化测试与验收、回避真实依赖、伪造数据，或在关键路径用 Mock 代替要求的真实验证。
- 发现候选在执行期间被其他活动改变时，指出竞争状态并避免把旧结果归到新候选。
- 若能看到自身原生 Task/代理标识或启动的进程身份，按原样报告原生返回的 canonical name 或 ID、PID/exec handle；无法看到时明确写未知，不扫描或认领其他会话和进程。

## 主会话验收

Executor 返回后，主会话检查实际文件、差异、产物和验证结果，并把它们与 Task 验收逐项对应。至少确认：候选身份仍一致；关键命令确实执行；失败和未验证项没有被完成摘要掩盖；范围外内容未被纳入。

证据足够才接受。证据不足时定义一个新的有界核验或修复 Task；不要要求原 Executor 无限自我修正，也不要把同一实例当作独立审核者。
